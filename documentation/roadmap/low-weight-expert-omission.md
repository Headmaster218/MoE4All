# 低权重 miss 专家跳过分档提案

**尚未实现。本页不是当前配置说明，也没有已测得的加速百分比或最终质量损失。** 数字来自[2026-10-11 单次真实记录的局部删除分析](../evidence/campaigns/qwen38/2026-10-11-low-weight-expert-omission.md)。

## 建议分档

保留五档：原始、保守、均衡、激进、疯狗模式，不使用未测得的加速倍数或“质量无损”标签。原“强加速候选”改名“均衡”，原 low2、<7% 候选仅保留在历史数据中。设本层 miss 集合为 M；保守、均衡、激进要求所有 miss 同时满足条件。疯狗模式允许部分跳过，规则见下文。所有档均不删 hit/shared，默认保留实际计算专家的原权重。

| 档位 | 条件 | 触发层数 | 覆盖全部有 miss 层 | 合并 hidden P95 / max | 最差单路 max |
| --- | --- | ---: | ---: | ---: | ---: |
| 0 原始 | 所有选中专家正常计算 | 0 | 0% | 0 / 0 | 0 |
| 1 保守 | 恰好 1 miss，位于 low1，权重 <7% | 83 | 10.65% | 2.45% / 3.00% | 6.58% |
| 2 均衡 | 1/2 miss，全部位于 low2，各自 <9% | 206 | 26.44% | 2.99% / 4.68% | 7.65% |
| 3 激进 | 1/2 miss，全部位于 low3，各自 <9% | 300 | 38.51% | 3.08% / 9.34% | 9.69% |
| 4 疯狗模式（实验） | 保护核心、按单项与总预算筛选；此行统计稳态候选 | 749 | 84.60% | 5.81% / 9.41% | 20.56% |

覆盖率统一以 779 个有 miss 的层样本为分母，表示全部 miss 都可跳过的层。疯狗触发 749 层，其中 659 层全部 miss 可跳过，90 层仍有必算 miss；其他档的触发层均跳过全部 miss。误差为所有触发样本的局部统计，不混入不跳过时的零扰动。原始档的零仅指没有本提案引入的删除扰动。

**不能保证真实加速或最终质量逐档单调。** 更大的省略率会改变下一 token 的 Router、cache 和循环状态；后台竞争也可能留下等待。疯狗有明确单路尾部风险，保留研究用途，不作为自动默认；前三档也尚未通过质量验收。默认保持第 0 档，覆盖率不能换算成 tok/s 或质量损失百分比。

在低尾部风险更重要的场景，可以增加研究点“low2、每个 <5%”：覆盖 5.13%，合并 hidden P95 2.06%、max 2.12%。不建议一开始暴露所有 3/5/7/9% 与 low 的笛卡尔积给用户，先验证少量固定配置，再决定是否增设精细参数。

## 为什么先用这些约束

1. **只针对 miss。** 已 resident 的专家没有上传等待可省，删除同样影响数值；先优化高价值 miss 关键路径。
2. **前三档要求全部 miss 合格。** 部分跳过可能仍需等待另一 miss，净收益更难预测；疯狗另做部分跳过 A/B。
3. **默认不重归一化，允许研究选择性补偿。** 激进的 300 层仅 5 层因重归一化改善，虽最大扰动从 9.34% 降至 8.49%，P95 从 3.08% 升至 3.98%。疯狗稳态候选仅 12/749 层改善，P95 从 5.81% 升至 6.37%，最大值反升至 13.21%。是否改善取决于被删和保留专家输出的方向、幅度，不是单看权重。missing 输出尚未计算，不能把事后最优选择当免费运行时判据；后续可以测试历史幅度/方向代理与部分补偿，shared 不缩放。
4. **前三档最多处理 2 miss。** 疯狗允许更多，但受核心、总预算和最少保留数量限制，不是全部 miss 无条件删除。
5. **权重与 rank 双条件。** low3、<9% 已纳入 9.34% 的局部异常；单纯“<10%”不能视为安全判据。

具体专家输出范数能解释异常，但得到它需要先算专家。历史 layer/expert 幅度代理可以作为后续预测器，不能把事后信息作为提前判定的可用输入。

## 疯狗模式：规则与生命周期

目标是减少冷状态同步载入数量，稳态后跳过绝大多数合格 miss。以下为待验证参数，不是质量安全界限：

| 内部阶段 | 必算核心 | 单个可删 miss | 本层省略总权重 | 最少保留 |
| --- | --- | --- | --- | --- |
| 启动 / 恢复 | top3 | <12% | ≤20% | 3 个 routed 专家 |
| 稳态 | top2 | <15% | ≤30% | 3 个 routed 专家 |

百分比使用选中 routed 专家的相对权重 `p_i = w_i / sum(w)`，shared 不参与该分母；实际 Accumulate 仍用原系数。原 trace 系数和接近 1，推广时不能把任意缩放系数当概率。零总权重或异常输入保持原路径。

逐层逐 lane：先保留 hit、核心；对非核心 miss 按权重从小到大筛选，在单项、总预算及最少保留数量内加入跳过 mask。预算外 miss 正常上传计算，被跳过者本 token 贡献零并列入后台载入候选。10 个选中专家理论最多跳过 7 个，本次最多实际跳过 5 个。全部 miss 被跳过则直接继续，否则只等剩余必算 miss；后台上传不成为当前 token 的依赖。

保留三专家与 70% routed 权重只是结构限制，不是误差上界；小权重专家仍可能有大输出，长期扰动也可能累积。

### 启动与切换

- 新生成 lane、上下文替换/压缩、不能连续延续的 KV 恢复进入启动阶段。普通增量续写不无条件重置；不能为切换一条会话清空全局共享专家缓存。
- 启动阶段也允许有限跳过，不要求长时间全量暖机。核心和预算外 miss 同步补齐，跳过专家后台补热；核心 miss 的冷启动成本不可消除，不能承诺立即达到稳态速度。
- 阶段按每 lane、每层实际 resident 权重占比判断。建议第一版实验采用：连续 8 次 decode 前向的滑动平均达到 85%，且后台无积压，转稳态；连续 2 次低于 65%，或后台落后超过 2 个 token 周期，回恢复阶段。使用原 Router 与 residency 统计，不以删除后的权重自证命中率。门槛尚未标定，也不是质量检测器。
- 后台载入去重、限流，确定性需求优先。结合重复省略频率和等待年龄排序，防止同一专家永久被忽略而得不到载入；低价值背景传输不得阻塞新核心需求。
- 上传后成为 hit 就照常算，不做永久剪枝。工作集能放进 cache 时省略会随补热减少；持续换工作集时不能保证一直跳过近乎全部 miss。
- 多槽阶段独立，专家缓存/载入共享；其他 lane 需要正常算的专家必须满足，不做批级删除。

## GPU 运行时接入约束

该方案面向已有 GPU residency 判断之后的 Decode，不要求把 LRU 一并迁移到 GPU，也不是本次文档 PR 的实现内容。

- 在同一个 Router/residency 阶段产生计算 miss mask、跳过 mask 和后台载入 mask，优先留在 GPU；不得重新引入每层 CPU 同步来判断档位。
- 当前 token 跳过的专家必须贡献零，保留其余专家原权重和 shared；不能读到旧 scratch 槽的残留输出。合成 Accumulate mask 与上下游 barrier 需单测验证。
- 档位对每个生成 lane 分别判断；批内同专家被别的 lane 需要时仍正常上传/计算，不能把一条 lane 的删除变成全批删除。
- 跳过只影响本 token 的计算，不表示专家已 resident。后台传输完成并满足 fence/内存可见性后才发布 LUT；载入失败可保持 miss，下次再走确定性路径。
- 后台上传不能覆盖本轮或在途 GPU 使用的专家/scratch，需遵守当前 pin、slot generation 和统一显存生命周期。取消、KV spill、Prefill、视觉/Embedding 切换前正确退休未完成传输。
- 确定性需求上传优先于后台载入；后者若拖慢下一层/下一 token，不应继续以“覆盖当前计算”为由占队列。节省等待还须扣掉额外 Router 判定、通知、提交和后台干扰成本。
- 初期只接普通文本 Decode；Prefill、MTP draft/verify、视觉及特殊图保持原路。请求级选择、token 边界生效，不能全局切档改变正在运行的其他请求。

上述内部阶段、阈值及后台预算需要闭环标定。直接把 trace 的误差门槛当实时可观测误差，或逐层下载真实 hidden 检查，会引入事后信息与同步开销。

## 如何标出“加速档”与“质量损失档”

现在只能填写上表的**跳过覆盖与局部扰动**，不能按覆盖率换算 tok/s，也不能把 2.76% hidden 扰动写成 2.76% 质量下降。

建议验证顺序：第 0 档与第 1、2、3 档做匹配对照，先把第 2 档作为主要候选；第 4 档单列研究矩阵，分别验证启动与稳态。每个档位同时测以下几类指标：

- 速度：匹配基线的平均/中后段 tok/s、每层 exposed miss wait、后台传输干扰与总 GPU 时间；单路和多路分开报告。
- 局部差异：强制一致输入下的 hidden/单路/FFN 误差及 logits 差异；不能当作自由生成的长期结果。
- 长程质量：真实代码测试通过率、可核对任务正确率、工具成功率、重复/格式错误与长推理完成率；使用多 Prompt、多 seed，以及独立留出的任务。
- Cache 反馈：实际省略频率、下一 token 的 residency、驱逐与上传量、Router 漂移；重跑完整流程而非固定原 trace 命中表。
- 生命周期：全冷启动、换任务、正常增量、压缩恢复、多槽竞争、后台积压/取消及连续省略，检查请求/arena generation；不能用稀疏原 trace 代替闭环测试。

完成后才能报告“实测平均 +X% / 某评测 -Y 个百分点”，同时附模型、设备、上下文和任务。当前五档是保留的设计选择，不表示发布就绪；无净收益的档位需重新调参或继续标为实验。

所有近似档都必须显式 opt-in，返回/日志保留生效策略和省略计数，便于排查输出差异。所谓“自动收益判断”也只能优化速度，不能凭短时速度自动证明质量安全或替用户开启近似计算。
