# 量化 MoE 专家的异构执行成本模型与收益边界

## 摘要

GPU 专家缓存出现 miss 时，可以搬运压缩权重后由 GPU 计算，也可以直接在 CPU 上读取 RAM 中的权重并返回结果。两条路径的优劣，取决于**结果何时在关键路径上可用**，不是 CPU 峰值 FLOPS、内存跑分或 DMA 峰值中的任意单项。

本文建立工作负载、CPU 解码与计算、传输、并行重叠的分层模型，用于回答三个问题：当前瓶颈是什么；增加哪种资源有用；什么条件下值得选择 CPU 路径。硬件型号只作为参数实例，不作为准入白名单。

本页是方法论，不保存滚动 benchmark 排名。具体指令计数、5600X 历史实测、25 GB/s 算例和候选 CPU 分档见配套的[实验与证据记录](../../evidence/campaigns/qwen38/2026-10-23-cpu-expert-offload.md)。其中的静态模型不是未测试设备的性能保证，也不改变当前默认策略。

## 1. 问题定义与适用范围

设某层路由已经确定，命中专家可以在 GPU 计算，缺失专家需要另一条路径补齐。比较对象必须使用同一个路由事件、相同的输入、量化格式和最终结果合并位置。

```text
路径 D：RAM 权重 -> 传输 -> GPU miss FFN -> 合并
路径 C：RAM 权重 -> CPU FFN -> 返回结果 -> 合并
共同工作：GPU hit/shared FFN，以及两条路径之后相同的层尾计算
```

研究目标是减小这一事件暴露出的等待，并最终缩短完整 Decode 前向。不以“用满 RAM 带宽”作为目标：CPU 即使未用满 RAM，也可能快过 PCIe 路径；用满 RAM 也不保证比另一条路径更快。

本模型首先适用于权重完整驻留 RAM 的单 token 专家 FFN。SSD 读取、多个 token 共用权重、UMA、并发槽位及其他 CPU 工作，需要增加对应成本，不能直接套用本文单事件的数值。当前有限实现的格式、几何和模式约束见[CPU miss 入口](../../../crates/infr-vulkan/src/cpu_miss.rs)。

## 2. 符号与计时口径

| 符号 | 含义 |
| --- | --- |
| `d, h` | 专家输入/输出宽度、FFN 中间宽度 |
| `m` | 本次事件的缺失工作；同时记录 assignment 数和去重专家数 |
| `S_C` | CPU 实际计算的专家压缩权重字节数 |
| `S_D` | 另一条路径实际需要搬运的字节数 |
| `S_RAM,p` | CPU 阶段 `p` 真正从 DRAM 读取的字节数 |
| `N, f` | 可用于计算的物理核心数、工作期间持续频率 |
| `N_eff,p` | 阶段 `p` 考虑任务尾部后的有效并行度 |
| `W_p` | 某个明确实现的阶段计算成本，单位为核周期 |
| `B_RAM, B_D` | 对应访问模式下持续 RAM 带宽、DMA 载荷带宽 |
| `A_D` | 传输前后的录制、提交及相关控制开销 |
| `V_D` | 尚未计入其他项的队列等待和可见性依赖 |
| `D` | 从共同起点到 GPU 可安全读取 miss 权重的时间 |
| `C` | 从共同起点到 CPU 结果可供 GPU 合并的时间 |
| `H_D, H_C` | 两条路径各自的 GPU hit/shared 工作完成时间 |
| `G, M` | GPU miss FFN 成本、CPU 结果的 GPU 合并成本 |
| `K_D, K_C` | 依赖满足后仍暴露的恢复控制成本 |

“传输开销”统一指录制、提交和相关控制；“实际搬运”只指字节传送。两者分别记录。API 调用返回时刻不等于 GPU 开始时刻，不能默认把 API 全耗时都放在关键路径上。

所有时间使用同一个事件起点，例如路由结果对控制线程可用时。输入回读、提交、GPU 事件的时间基准必须对齐。不同事件的独立 P50 不能相加还原一个真实事件。

单位固定为 `B`、`GB/s = 10^9 B/s`、`GiB/s = 2^30 B/s`、`us`。比较前先换算，不把 25 GB/s 与 25 GiB/s 视为同一个条件。

## 3. 从量化格式推导工作量

### 3.1 三个矩阵与压缩字节

对普通 Gate/Up/Down 专家：

```text
Gate: [h, d]    Up: [h, d]    Down: [d, h]
权重数量 P = 3 d h
点积的有用浮点运算量 F_dot = 6 d h
```

`F_dot` 不包含反量化、查表、缩放、SiLU、归约和控制，不能单独用于判断 CPU 是否足够快。若量化格式 `q` 每 `b_q` 个权重使用 `a_q` 字节，则矩阵的实际行布局决定 `S_q`；存在行 padding 或块尾时按真实分配求和，不只用平均 bpw。

以本地有限 CPU 路径支持的 `d=2560, h=640` 为例：

| 部分 | 格式与块布局 | 权重数量 | 压缩字节 |
| --- | --- | ---: | ---: |
| Gate + Up | IQ2_S，82 B / 256 权重 | 3,276,800 | 1,049,600 |
| Gate + Up | IQ3_S，110 B / 256 权重 | 3,276,800 | 1,408,000 |
| Down | IQ4_NL，18 B / 32 权重 | 1,638,400 | 921,600 |

因此完整专家分别为 `S_IQ2=1,971,200 B`、`S_IQ3=2,329,600 B`。这不是所有模型或所有量化专家的统一大小。

### 3.2 解码不是免费的

对当前这类 AVX2/F32 内核，每 256 权重的大致工作组成如下，具体指令选择仍以对应汇编为准：

| 格式 | 解码与符号 | 缩放和点积 |
| --- | --- | --- |
| IQ2_S GU | 32 个码本索引；紧凑表展开与整数转浮点；32 次符号掩码处理 | 32 次八路向量缩放、32 次八路 FMA，另有 block/group scale |
| IQ3_S GU | 64 个四元素码本索引；32 次向量拼接；32 次符号掩码处理 | 32 次八路向量缩放、32 次八路 FMA，另有 block/group scale |
| IQ4_NL Down | 8 组半字节拆包/查表；32 次整数展开与转浮点 | 32 次八路向量缩放、32 次八路 FMA |

此外，每输出行要归约向量累加器，Gate/Up 后还有 SiLU 和乘法。输入和小表可以从缓存复用，但仍消耗加载、执行端口和寄存器资源。缓存命中不等于这些指令没有成本。实现见[量化 CPU 内核](../../../crates/infr-vulkan/src/cpu_miss/kernels.rs)。

### 3.3 计算字节与搬运字节未必相等

若同一专家的部分权重已在 GPU，`S_D` 可能小于完整 `S_C`；若多个 assignment 共用专家，搬运字节和 CPU 工作也可能分别去重。必须从真实角色与路由计算，不能用“一个 unique expert”替代所有成本。

同理，`S_C / T_FFN` 是**有效权重处理吞吐**，不是 DRAM 硬件计数。热权重可能来自 L3；小表和激活也可能产生额外 DRAM 流量。判断是否饱和内存需要匹配的流式内存基准或硬件计数。

## 4. CPU 成本模型

### 4.1 先找执行资源约束

对一个固定内核，可分别估计：

```text
W_front = I_macro / dispatch_width
W_ports = max_j(resource_work_j / throughput_j)
W_dep   = 由实际数据依赖图、指令延迟和独立累加链确定的成本
W_p     以这些约束为起点，再用匹配微基准标定
```

汇编行数不等于 macro-op 数。只有明确处理比较分支融合、指令拆分等条件后，才可用行数给出乐观分派下限。`max(W_front, W_ports)` 是资源下限，不是完整耗时预测。简单累加链估计还可能被跨行乱序执行缓解，不能称为处理器的绝对物理上限。

必须固定量化格式、行 tile、累加顺序、编译目标与编译器。把两行参考内核的估算套给单行生产路径，或者把更高 ISA 的结果套给 AVX2，都不成立。

### 4.2 分阶段建模，不把内存和计算简单相加

对阶段 `p`，一个便于标定的近似是：

```text
T_p ~= max(W_p / (N_eff,p f), S_RAM,p / B_RAM) + epsilon_p
T_FFN = T_GU + T_SiLU + T_Down + T_phase_sync
```

其中 `epsilon_p` 表示未被完全隐藏的依赖、缓存等待等剩余项。若 GU 计时已经包含 SiLU，不能再加一次。Gate/Up 和 Down 存在数据依赖，两个阶段不能当成完全并行。

这里的 `max` 假设计算和读取可以充分流水，是乐观起点；真实实现可能有部分串行，需由 `epsilon_p` 和分阶段观测修正。权重来自缓存时，`S_RAM,p` 也不能仍按完整权重重复计入。

### 4.3 核心数受离散任务限制

若某阶段有 `J` 个近似等成本任务，每个成本为 `w`：

```text
T_compute ~= ceil(J / N) w / f
N_eff = J / ceil(J / N)
```

所以增加核心后的曲线通常是阶梯状，而不是直线。当前参考分块的单专家 GU 有 `640/32=20` 个任务，Down 有 `2560/128=20` 个任务。把 14 核直接当作 14 倍单核吞吐，会漏掉最后一批任务的空闲。

任务不等成本时，至少同时考虑 `sum(t_i)/N` 与 `max(t_i)`，再评估实际调度尾部。多个 miss 会增加任务数，但不能保证总 FFN 时间按 miss 数或核心数线性变化。源码入口见[阶段分块](../../../crates/infr-vulkan/src/cpu_miss.rs)。

这个表达式假设同构核心和近似相同的持续频率。P/E 混合核心应分组标定任务能力与共享瓶颈，不能把总物理核数直接代入同一个 `f`；SMT 线程也不等于新增一个物理计算核心。

### 4.4 完整 CPU 结果就绪时间

```text
C = T_input_handoff + T_job_start + T_FFN + T_result_return + T_result_visibility
B_CPU,compute = S_C / T_FFN
B_CPU,ready   = S_C / C
```

前者适合诊断计算内核，后者更接近路由选择需要的成本。只有完整结果可被消费后，才能认为 CPU 完成了这次替代工作。

## 5. DMA 与 GPU 成本模型

```text
D ~= A_D + S_D / B_D + V_D
```

这是从同一起点到权重可被 GPU 安全读取的估计，不是孤立 copy timestamp。`A_D`、`V_D` 必须按不重叠的区间定义，不能把 profiler 的父 span 和子 span 再次相加。不同阶段能够重叠时，应使用事件 DAG 的最长依赖路径而非机械求和。

使用多种载荷大小拟合固定项和持续带宽，并以独立样本验证。大块 DMA 的峰值不是一组小型 Gate/Up/Down 上传的完整吞吐。CPU push、导入 DMA、staging fallback 需要分别标定，不能共用一个固定截距。

搬运完成后还有 GPU miss 计算 `G`。其数值应在命中专家工作之外测量，不能把下一层 router 或后续公共计算算作本次 miss FFN。

## 6. 重叠与收益边界

### 6.1 同一起点的关键路径

在 hit-first、GPU miss 计算依赖 hit 工作和权重到位、CPU merge 依赖 hit 工作和 CPU 结果的条件下：

```text
L_D = max(H_D, D) + G + K_D
L_C = max(H_C, C) + M + K_C
Delta = L_D - L_C
```

`Delta > 0` 才表示这一事件的 CPU 路径更早完成。公共层尾不重复计入。若计算被细分为多段交错执行，改用对应事件 DAG；上述二分模型只是它的简化形式。

通常不能默认 `H_C=H_D`：CPU 计算、内存访问、上传或忙等线程可能拖慢另一条 GPU/控制路径。跨路径的资源竞争必须实测或保留不确定项。

### 6.2 重叠区域

为说明边界，暂令 `H_C=H_D=H`、`K_C=K_D`：

| 区域 | 局部收益 `Delta` | 含义 |
| --- | --- | --- |
| `C<=H` 且 `D<=H` | `G-M` | 两条等待都被隐藏，继续加速 CPU 或 DMA 不再直接缩短该段 |
| `D>H` 且 `C<=H` | `D-H+G-M` | CPU 全部被隐藏，DMA 有暴露等待 |
| `C>H` 且 `D<=H` | `H-C+G-M` | CPU 暴露等待，只能靠省掉 GPU miss 计算弥补 |
| `C>H` 且 `D>H` | `D-C+G-M` | 比较两条就绪时间差及计算/合并差 |

这张相图说明：CPU 比 DMA 稍慢仍可能有收益；CPU 计算吞吐高于 DMA 也不保证整轮提速。

### 6.3 带宽筛选线如何推导

在 `H=0`、忽略额外恢复差异时：

```text
C + M < A_D + S_D/B_D + V_D + G
```

若 `S_C=S_D=S`，可以把右边换成 CPU 结果就绪吞吐的要求：

```text
B_CPU,ready > S / (A_D + S/B_D + V_D + G - M)
```

只在分母为正、假设成立时使用。简单的 `T_FFN < S/B_D` 则是**内核初筛目标**，没有包含 CPU 交接，也没有利用省掉 GPU 计算的收益。它既不是必要条件，也不是充分条件。

以本卡讨论中的 `B_D=25 GB/s` 为条件，可以得到具体时间预算，但不能直接据此规定某个 CPU 型号以下永远关闭、以上永远开启。算例和单位换算见[配套记录](../../evidence/campaigns/qwen38/2026-10-23-cpu-expert-offload.md)。

### 6.4 还要检查后续成本

若 CPU 计算后仍需要将专家提升到 GPU，当前结果不应等待自己的 promotion，但上传仍可能影响后续层、缓存驻留和资源预算。必要时以多个前向为观察窗口，评估总 `Delta`，而不是只看当前 miss。

全命中层没有可替代的 miss 成本；高命中率会限制这项优化的整体收益。局部收益经实际出现频率加权后，才是完整 Decode 可获得的空间。命中率本身不能替代暴露等待的测量。

## 7. 资源敏感性与优化选择

| 改变 | 主要影响 | 何时不能按比例获益 |
| --- | --- | --- |
| 提高持续主频 | 缩短计算和部分控制 | 已受 RAM/同步限制，或多核频率低于假设 |
| 更宽分派、更多加载/整数资源 | 加速解码、索引和查表 | 累加链、执行端口或数据依赖已是主约束 |
| 增加物理核心 | 增加独立输出行的计算能力 | 任务数量不足、尾部批次、跨 CCD/NUMA、控制核被挤占 |
| 更宽 SIMD、更多寄存器 | 减少某些指令或增加独立行 | 需要新内核；标量查表不自动减半；不能直接承诺倍数 |
| 增加缓存 | 减少小表、激活或热权重的下级访问 | 计算瓶颈不变，或真实工作集无足够复用 |
| 增加内存通道 | 提高 DRAM 供给上限 | 解码/计算消耗不了新增供给 |
| 手写汇编 | 控制寄存器、调度和指令选择 | 原指令已经接近资源下限；驱动等待不因换语言消失 |

AVX-512 的 F32 实现与 VNNI/INT8 激活不是同一项优化。后者引入新的激活量化与误差预算，不得用它的吞吐证明原 F32 路径能够无损达到相同速度。

对给定实现，先绘制 `B_CPU,compute(N)` 和 `B_CPU,ready(N)`，再叠加 DMA 参考线。加上 RAM 上限及任务阶梯，曲线拐点才具有指导意义；不要只画从单核无限延长的理想直线。

## 8. 参数标定与独立验证

### 8.1 建立可追溯输入

冻结源码 commit、补丁、编译器/参数、内核版本、成品 hash、模型与量化身份。记录物理核心及 SMT/CCD/NUMA 分配、持续频率、内存拓扑、GPU/驱动、是否有争用。

原始权重、汇编和计时数据只作为输入或证据保存，不为写方法论重新复制一份。后续新生成的数据遵守工作区磁盘规则；本次历史源没有统一 manifest 时，应如实说明其溯源缺口。

### 8.2 标定集

1. 用真实专家格式分别测 GU/SiLU、Down 和完整 FFN；保留原始样本，报告 P50/P90/P95 与轮间范围。
2. 扫描物理线程数、任务粒度和 1~3 miss；分开热权重、轮换大于 LLC 的工作集和真实路由回放。
3. 对实际上传路径测不同字节规模的固定开销、搬运、可见性和恢复；同时测 CPU 输入/结果交接。
4. 在与 GPU 共运行的条件下测 `H_C-H_D`，不能把完全隔离的 CPU 时间当成集成时间。

轮换工作集不是强制清空缓存；`S/T` 也不是内存控制器计数。标定报告必须写清这些限制。

### 8.3 验证集

用未参与参数拟合的专家、miss 序列和上下文验证 `C, D, H, G, M` 与 `Delta`。先比较真实事件的预测误差，再做匹配的完整前向/模型 A/B，不以同一组拟合数据证明模型正确。

不同 CPU/GPU 算术可能改变后续采样与路由。先用固定输入/专家回放隔离性能，再独立验证完整模型的数值和质量；不能把路由轨迹已变化的两组层样本直接当作受控提速。

### 8.4 不确定区而非单点开关

只有收益超过测量波动、模型误差和资源竞争的安全余量，才视为有依据的候选。若预测区间跨过零，标记为待测，不用正好落在 25 GB/s 附近的单个 P50 决定默认策略。设备选择、模式回退和质量验收仍是独立条件。

## 9. 指导准则

1. 先按真实量化格式数清解码和计算工作，再讨论硬件升级，不能只比较峰值 FLOPS。
2. 比较完整结果的关键路径，不比较孤立 memcpy 与孤立点积。
3. 使用有效物理并行度，不用逻辑线程数或总核心数直接线性外推。
4. 把带宽门槛转成对应专家的时间预算，并明确其未计入的成本。
5. CPU 型号是算例；可迁移的准则是收益不等式与本机标定结果。
6. 模型约束某个实现和场景，不证明所有可能算法的绝对极限，也不授权改变默认路径。
