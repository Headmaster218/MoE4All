# 0.9.0 → 0.10.0 变化记录

## 版本事实与读法

范围 `release-0.9.0`（`ed62393068679573afe94a1472454efe7eae0f15`）至 `release-0.10.0`（`7b4a9411e9c7524f8dc6ae2603c62d5f338190dc`），包含98个提交（含合并和并行Agent/doc分线）。当前规则由架构/配置页给出，本页保存为什么变、哪些失败、测过什么。不把代码merge当作全硬件验收，也不把commit message里的屏测提升改写成普遍保证。

## Prefill、预算与 QSA

- `7d83e9195`/`b3c27d42a`复用Prefill GQA KV读并融合QSA attention；`3abb84bbd`融合sigmoid gated RMSNorm，`af4015703`融合DeltaNet alpha/beta；`32c06058a`复用scratch减少峰值，`7e14cc6c0`记录workspace fallback。
- `e668c8827`保留shared-expert Prefill输出，属于正确性，不能用错误路径测速。
- `196c30263`仅限制Windows Intel Xe1自动VRAM为75%/85%；`a5a004ec4`重平衡自动GPU档。RAM启动预算依旧是free-3GiB/total-14GiB；离散GPU两档ubatch从4096开始，按真实放置fallback，不沿用旧“保守1024/激进2048”。
- `565578cdf`借未提交KV，`70067ca83`只增长选中slot，`9789f456f`dedicated DMA，`5324b8c7c`跨chunk权重预取。`7903454b3`测CPU/DMA竞争。
- `c853ec6f0`实时联合ubatch/ring/QSA规划，避免未来深度和idle slot高水位过早挤压当前Prefill。长Prefill仍独占ring，不在其间插Decode；也不把所有模型的legacy scheduler一概写成qwen4 worker。

过程、matched数字和失败见[Prefill/MTP专项](../campaigns/qwen38/2026-10-06-prefill-and-mtp.md)。资源事实见[生命周期](../../architecture/memory/runtime-resource-lifecycle.md)。

## MTP

`69d8d6203`将head历史限制到独立窗口；`5c85a1f54`按接受率决定并发模式；`1899765ad`让MTP跟随普通ubatch；`730b1354a`收敛执行与fused paths。head horizon、target cutoff、VERIFY rows和未来候选数是四个概念，不能混用。默认多活跃回退plain，显式并发才做8cycle/80%probe；旧原型ready/frontier panic也保留在专项。高接受率数数收益不代表普通问题。

当前边界见[MTP](../../architecture/runtime/qwen38-mtp.md)，早期9月数字继续按原提交保存。

## Ordinary Decode 与 opt-in CPU miss

`75abee7bc`路由sigmoid；`1be9de19f`/`08ee5c89c`HC down/injection；`dca5cebeb`按设备prefetch；`2fe54f1d4`immutable IQ码本/row groups；`b9b842ff3`/`e1d6b0abd`测得的deep三/双路Down promotion overlap；`08ca51a5f`精确QSA count prefixes；`07c7b0e97`router-to-hit handoff。

`a1f0a8e3f`私有CPU task pool，`cd44a8215`实验expert miss，`cba30dd50`向导入口。完整RAM、scalar、shape/量化限制及physical worker策略见[CPU架构](../../architecture/runtime/cpu-miss-offload.md)。最终CPU screen持平，默认关闭；独立GPU ABBA的约6%单路收益不归功于CPU miss。

E1..E16包括staging回退、融合无收益、QSA prepare hash分歧和更少barrier却更慢，全部见[Decode专项](../campaigns/qwen38/2026-10-08-decode-and-cpu-miss.md)。否决项不在架构能力表里列为已采用。

## 时间线、吞吐与会话缓存

`e448849a2`有界异步collector，`0d8bff8e7`既有同步点队列overlap，`8aaf93ca6`mapped-copy spans。它们有测量开销，不能用trace中的wall代替clean速度。

`38f60a9aa`slot/total interval throughput，`f300a48ad`1.5秒刷新与chunked Prefill平滑；API全程均值、interval、SSE frame和共同窗口分开。`b530332c7`让idle SSD KV写入让出gate；live状态直到KV+MTP持久化成功后才能释放。[在线对账](../benchmarks/2026-10-09-live-service-reconciliation.md)保留性能回退、resident idle KV挤压ring与未完全解释的长三路差距。

## 正确性与失败诊断

`53afa86f3`保留aux workspace并序列化shared command pool的一次性state transfer；修复前Vision overlap0xC0000005、修复后有限组PASS，见[事故](../incidents/INC-20261009-vulkan-aux-command-pool.md)。

`ef4d972b2`修复混合batch sampling suffix，短继续请求也能污染其他Decode lane，见[事故](../incidents/INC-20261010-mixed-batch-sampling-suffix.md)。`1d343805b`补host allocation失败的内存/commit/系统错误诊断，不冒充修好了未知VirtualAlloc根因。`5b3a7a65a`把HTTP整体body上限提高到64MiB。

## 图片与跨平台发行

`cae8a4f0f`更多常用图片格式与解码诊断，`b62d38ba5`ICO RGBA测试，`0012f0e81`有界HEIC/AVIF+固定native build；`860777dac`随包image-codecs、单文件Linux SH。`895dd2eb1`记录standalone体积，不能套用成最终整包增量。

`105931c1f`Linux向导，`c372e6ca3`override/确认，`5396ffd08`MTP greedy，`93aa1280a`实验Linuxrelease，`c579bd34a`混合CPU预留/Vulkan设备选择，`d305d431b`Windows进程级ExecutionPolicy，`b6c67717e`简化向导/复用配置。Linux是实验发行，单SH不要求用户装Python，源码codec构建依赖另算。向导检查更新不代表获准自动安装。

CI改进包含Linux glslc executable target、tag-only versionvalidation、无Vulkan Windows launcher smoke、native codec/Rust cache隔离、codec hooks/strictlints、worker容量自适应与两平台release pipeline验证。静态/unit/打包检查不等于真实Linux GPU门禁。见[源码构建](../../development/building-from-source.md)与[Linux指南](../../guide/linux-build-and-run.md)。

## Agent、文档与仓库卫生

早期provider/plugin引入、guided settings、first-run及独立distribution profile，经`5a96933ae`品牌化/数据隔离，`3cd454f10`同步插件isolation/updater修复。0.10.0固定DSH+八插件，复用生态、默认MoE4All、连接外部引擎；正式EXE和后续preview不属于本tag，见[当前产品架构](../../architecture/product/agent-distribution.md)。

`dc3da45c5`统一0.9文档，`6edf37df6`补draft覆盖，`37d3a26f6`/`b73ac1e1f`修Agent方向；`4da2ea70b`48h线上审计保留有限结论。`81983b05b`ignore raw benchmark/LF，`abe744ee1`ignore本地upstream研究。README的多次数字更新是不同测量/展示阶段，不覆盖早期证据。根CHANGELOG在此tag没有完整0.10.0条目，因此不能仅按它重建变化。
