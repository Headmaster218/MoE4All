# INC-20260925：冻结的专家 LUT 槽位导致重复输出

## 摘要

0.8.0 用户报告在短上下文生成中进入无意义的重复片段，例如连续重复 `vec`、`4`、`t` 和 `acity`。
问题不要求长上下文，也不是 32K KV 分段边界本身导致；它属于分页式 MoE 解码/VERIFY 的物理地址生命周期错误。

## 影响

- 请求可以继续生成而不崩溃，但 token 分布已经被破坏。
- 表现通常是短片段循环、词片重复或突然失去语义。
- 只看 HTTP 状态、显存占用或吞吐无法发现，必须检查输出正确性。

## 被破坏的不变量

解码/VERIFY 会把当前路由专家的物理地址写入仅追加的 LUT 带。命令仍未排空时，带是不可变的，
因此其中引用的专家槽位也必须保持原位。

原实现允许后续惰性运行时临时工作区或统一显存声明回收、移动这些专家填充槽位。LUT 带仍指向旧地址，
GPU 随后读取错误内容。该错误不一定触发越界或 Vulkan 验证错误，而会静默污染 logits。

## 修复

提交 `7a1830fa` 同时收紧了两个生命周期边界：

1. 在第一个专家 LUT 窗口冻结前预留注意力、采样和 argmax 等尾部临时工作区，避免录制中途再借用专家槽位。
2. 记录每个冻结窗口实际路由的常驻槽位，并在命令流排空前将其加入统一声明的保护集合。
3. 全常驻快速路径没有 CPU 路由 ID 列表时，保护完整 LUT 窗口。
4. 排空后与带游标一起释放保护；错误路径由 RAII 守卫清理，避免保护泄漏到下一次执行。

只保护实际可解引用的 routed slot，而不是长期 pin 住整个 Expert pool，因此仍保留统一显存弹性。

## 回归保护

- `frozen_lut_protection_covers_only_routed_resident_slots` 验证去重、槽位映射和非法专家拒绝。
- 尾部临时工作区尺寸测试覆盖采样 lane 数和独立注意力的最深 lane。
- 代码级约束保证 `clear_frozen_moe_lut_slots` 只在流排空或执行拆除边界调用。

## 后续验证

单元测试保护地址簿记，但发布验证仍应包含：分页式 MoE、短上下文、普通解码、MTP VERIFY、并发 lane 和长时间输出
正确性。吞吐测试不能替代重复片段与 token parity 检查。
