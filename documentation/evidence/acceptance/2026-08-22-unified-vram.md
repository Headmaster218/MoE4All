# 统一显存验收 — 2026-08-22

> 历史性的第一阶段结果。下文所述的持久 Embedding 与独立运行时预留行为，已由 2026-08-24
> 验收的完全弹性设计取代；参见
> [`unified-vram-elastic-acceptance-20260824.md`](2026-08-24-elastic-unified-vram.md).

## 结果

原生 LLM 和原生 Embedding 引擎现在共享一个逻辑显存 arena。该 arena 可跨越多个物理 Vulkan
分配，但分配、驱逐、复用和记账均为全局操作。Embedding 权重是该 arena 内的持久分配；Embedding
运行时缓冲区借用冷专家槽位，并在释放时原位恢复受影响的专家代次。

这完成了统一显存管理的预期第一版。Vision 和草稿模型分配类别留待后续集成。动态 KV 分配有意
不在本次范围内。

## 实现

本地提交，按依赖顺序排列：

1. `5aeb58b` — 统一逻辑范围分配器。
2. `02250a3` — 共享的映射 ReBAR 后备分片。
3. `c944e04` — 分页器向辅助引擎出借冷专家槽位。
4. `bc4fc93` — 原生 Embedding 使用 LLM Vulkan 设备、队列和统一 arena。
5. 最终验收提交 — 修复辅助执行锁定并公开启动记账信息。

最终锁定规则：

- 主 LLM 执行会在已提交工作可能引用专家槽位期间持有读租约。
- 辅助执行在记录静态图期间不持有该读租约，因为图记录可能惰性分配瞬态缓冲区。
- 需要专家槽位的辅助分配会取得写租约，因此等待任意飞行中的 LLM 执行，而非使其槽位失效。

这修复了统一 arena 已满时，同一线程尝试从读租约升级到写租约所导致的首次请求死锁。

## 性能验收

下方所有测量均使用 APEX Balanced 和 8 GiB 专家缓存设置。预填充使用 4096 个新 token 并重复两次。
解码使用 1000 个 token；原始 500-token 冒烟值不用于对比，因为其过度放大了冷缓存启动的权重。

| KV | 深度 | 操作 | 历史矩阵 | 统一显存 | 变化 |
|---|---:|---|---:|---:|---:|
| Q8 | 0 | 预填充 | 2881.8 t/s | 2855.6 t/s | -0.9% |
| Q8 | 250K | 预填充 | 477.3 t/s | 477.9 t/s | +0.1% |
| F16 | 0 | 预填充 | 2904.7 t/s | 2844.2 t/s | -2.1% |
| F16 | 250K | 预填充 | 431.5 t/s | 437.8 t/s | +1.5% |
| Q8 | 0 | 解码 | 93.0 t/s | 84.4 t/s | -9.2%* |
| Q8 | 250K | 解码 | 41.1 t/s | 41.2 t/s | +0.2% |
| F16 | 0 | 解码 | 91.8 t/s | 82.6 t/s | -10.0%* |
| F16 | 250K | 解码 | 32.5 t/s | 31.7 t/s | -2.5% |

`*` 历史 0 深度解码条目是单次样本，与后来的三次重复对照范围不一致。例如，统一前 Q8 d0/c10g
对照为 84.7 t/s（83.5–86.3），其中包含当前 84.4 t/s 的结果。当前 Q8 d0 运行也与历史 d0/c8g
行具有完全相同的 95.024% 命中率及命中/未命中计数。因此，上文透明保留 93.0/91.8 样本，但其不足以
作为统一 arena 回归的证据。主要目标长上下文 Q8 未变化。
