# DeepSeek V4 Flash / RX 7900 XTX 结项

日期：2026-08-24

分支：`feat/deepseek-v4-flash`

功能基线：`b007730`（`feat(deepseek4): add FP8 KV and MXFP4 indexer`）

性能头：`f2fb30f`（`perf(vulkan): vectorize decode f32 GEMV`）

兼容性结项：`7935cf8`（`fix(pager): preserve full-host down overlap`）

模型：`DeepSeek-V4-Flash-0731-AD-MXFP4`，四个 GGUF 分片

机器：Radeon RX 7900 XTX 24 GiB，Windows Vulkan

## 1. 最终状态

DeepSeek V4 Flash 现可通过原生 `infr` 图加载和生成，使用随附的压缩注意力拓扑、FP8 KV、MXFP4 索引器状态和分页式 MXFP4 专家。DSpark 尚未实现。
在测得的 40 GiB 有界 RAM / SSD 配置下，本优化专项以约 **4.3 解码 token/s** 结项。原始 17--25 token/s 目标在该存储层次结构下无法达到：
剩余主导成本是专家缓存未命中流量，而非缺少某一个计算内核。

保留策略是**包容式主机影子副本**。RAM 预算允许时，每个显存常驻专家都会保留不可变的 RAM 字节。这会在 RAM 预算内复制显存工作集，
但使显存驱逐仅成为元数据操作。测得从映射的 ReBAR 读回已驱逐专家仅约 44 MB/s，因此部分排他的层次结构要么会在 GPU 读取上停顿，
要么会从 SSD 重建受害块。

`7935cf8` 后未运行基准测试：该提交仅恢复既有的完整主机存储 Down 重叠路径，测得的有界 RAM/SSD DeepSeek 路径保持不变。

## 2. 可复现的最终运行

缓存追踪来自以下命令形状：

```text
infr bench -p 0 -n 128 -r 1 --ctx 16k --dev Vulkan0 \
  --set device.vram_budget=22g \
  --set device.vram_reserve=512m \
  --set paging.dram=40g \
  DeepSeek-V4-Flash-0731-AD-MXFP4-00001-of-00004.gguf
```

环境：`INFR_PAGER_PROFILE=1`、`INFR_PAGER_TRACE=<path>`、`INFR_SUBMIT_DISPATCHES=16`。性能分析运行报告 4.2 t/s；
相邻的未性能分析最终运行报告 4.3 t/s。

最终测得的缓存状态：

| 专家载荷 | 147.17 GB，33,024 个块 |
| 一个 MXFP4 专家角色块 | 4.25 MiB |
| 显存专家 arena | 12.67 GiB，3,052 个块 |

| `99e6e40` | 添加单 token、`hc=4` 并行 Sinkhorn 内核。短缓存热测试中 A-B-B-A 约从 8.0 升至 8.7 t/s。 | 仅发出恰有一行且 `hc=4` 的门控 HyperConnect 的图会选择它；目前为 V4 专用。 |

解码和单行 F32 GEMV。其中仅分页器调度存在明显的不兼容性能交互，且由 `7935cf8` 门控。

## 4. 保留的优化和已拒绝的实验

因具有真实的孤立或端到端收益而保留：

- V4 安全的自动显存规划和自适应常驻权重打包。
- 解码专用的 HyperConnect Sinkhorn。
- 并发有界主机提升和全角色批处理。
- 完整块 MXFP4 反量化。
- Vec4 F32 解码 GEMV。

未作为性能变更保留的测得实验：

| 实验 | 观察 | 决策 |
|---|---|---|
| 更宽的 MXFP4 `dqblk` 映射 | A/B 中 6.8 与 6.9 t/s | 无收益。 |
| 不限提交批处理 | 6.8 与 6.9 t/s；其他运行退化 | 保留拆分/16。 |
| DP4A MXFP4 变体 | 早期小幅收益，但后续可比运行中为 5.9--6.3 t/s | 劣于共享块解码。 |
| F16 HyperConnect 临时量 | F32 为 7.3--7.5 与 8.2--8.3 t/s | 负面。 |
| 将 HyperConnect 拆为四次调度 | 8.2 与 8.3--8.4 t/s | 调度成本抵消并行度。 |
| 非时序 ReBAR 写入 | 2.7--2.8 t/s 且不稳定 | 无稳定收益。 |
| 仅 Windows 每片句柄扇出 | 2.7--2.9 t/s | 没有请求级批处理不足以奏效。 |
| 八路请求扇出 | 3.7 与 3.8 t/s | 开销过大。 |
| 丢弃包容式 GPU 影子 | 3.9 与 4.0 t/s，RAM 条件命中 60.6% 与 61.6% | 负面，并使驱逐恢复昂贵。 |
| 扁平外层并行复制 | 3.9 与 3.9 t/s | 中性。 |

不同 `tgN`、缓存大小或性能分析模式的数字不作为加速进行比较。特别是短缓存热 7--16 t/s 结果是诊断性的，并非最终 SSD 支持吞吐。

## 5. 完整影子副本模拟

模拟器将记录的路由追踪重复至稳态，并为显存和包容式 RAM 运行独立的精确 LRU。它以 12.67 GiB 显存 + 40 GiB RAM 下的 4.3 t/s 校准：

```text
token_ms = 72.57
         + 0.2396 * MXFP4_GPU_miss_blocks
         + 1.0170 * MXFP4_RAM_miss_blocks
```

`0.2396 ms` 是按单独测得的 18.6 GB/s RAM 到 ReBAR 速率传输一个 4.25 MiB 块。对于 IQ3_M 估算，块字节数和两个传输项均乘以
0.873，而计算/内核时间保持固定。因此这是保守的**尺寸效应估算**，不是 IQ3_M 内核基准测试。

当前 12.67 GiB 显存 arena 是保守值。13.47 GiB 已成功加载。按当前加载顺序，14 GiB 在最后 414 MiB 分配附近失败；14.5--15 GiB 是理论上的
加载后扩展点。即使理论上从 12.67 增至 15 GiB，在 SSD 未命中消失后也仅约增加 0.30 t/s，因此 RAM 容量和更小的专家块才是更大的杠杆。

## 6. 结项决策

- 保留包容式完整影子副本；不要重新引入 GPU 到 RAM 的驱逐复制。
- 将 13.47 GiB 视为已演示的最大显存专家 arena；以上更大行是模拟，不是配置建议。
- 将归档的路由追踪保留为未来缓存策略模拟的基线。
- 恢复 Ling 的模型性能工作。DeepSeek V4 仍受支持，但进一步提速工作应等待实质不同的存储配置或更长的代表性路由追踪，
  而不是继续一次性的内核调优。
