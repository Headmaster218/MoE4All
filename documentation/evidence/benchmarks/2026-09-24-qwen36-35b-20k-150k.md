# Qwen3.6 35B：20K 与 150K 输入

## 溯源信息

- 来源：checkpoint `ee492e2e7e2c177e4cf6700ca64ac72a412988f4` 中的 `README.md` 汇总表；该摘要由 `14505d5a`（2026-09-24）提交写入。此日期是文档记录日期，不等同于运行日期。
- 原始运行 ID、完整命令、运行 commit、binary hash、重复次数和原始日志未随汇总保存；保留已发布样本，不伪称可复现。
- 模型：`Qwen3.6-35B-A3B-APEX-I-Balanced`，不启用 MTP。
- 硬件：AMD Radeon RX 7900 XTX 24 GiB、Ryzen 5 5600X、64 GiB DDR4、Windows 11。
- 配置：自动激进策略、Q8 K/V、greedy、关闭 thinking、单路生成。20K 使用 32K context capacity；150K 使用 `ctx=163840`。
- Prefill 和 Decode 速度单位为 tok/s；中段为生成 token 的 25%–62.5%，后段为 62.5%–100%。

## 结果

| 输入规模 / 负载 | 实际 prompt tokens | Prefill | Decode 全程 | 中段 | 后段 |

| 20K 简单问题 | 20,041 | 2,484 | 65.6 | 66.7 | 66.8 |
| 20K 复杂问题 | 20,049 | 2,421 | 59.1 | 59.5 | 62.6 |

## 解读限制

简单、复杂任务的输入长度在 150K 两组恰好相同，但 20K 组各自 prompt 长度不同；不能把不同任务间的速度差当成单变量因果关系。源汇总没有给出输出 hash、输出 token 数或逐次分布。
