# 2026-09-27 Qwen3.8 整体性能与稳定性

## 基线说明

本记录的目标是补充 0.9.0 发布前后的整机性能和稳定性证据，不是 `release-0.9.0` tag 的直接验收。测试工件绑定的源码提交为 `1f53db6b5db84e7eceb0a1c7254eee573c19b70c`，测试二进制 SHA256 为 `64cc6e636bb811f85ac9eb274960bb13ea028a815b058a509e7fba582608b81c`。该源码提交不属于 tag `release-0.9.0` 的祖先，且两者之间存在运行时源码差异；因此不能仅凭相同的产品版本名或二进制哈希，将结果解释为 tag 的性能表现。架构文档仍以 tag commit `ed62393068679573afe94a1472454efe7eae0f15` 为当前事实基线。

本轮工作树记录为 dirty，差异列在报告元数据中，涉及文档、测试脚本和 harness 子模块，不包括已记录的引擎源码文件改动；然而提交血统差异仍然存在，数据比较必须保留此限制。

## 测试条件

- 硬件：AMD Radeon RX 7900 XTX，24 GiB；Windows Vulkan，设备 `Vulkan1`。
- 模型：Qwen3.8-Flash-Next-AD，4.27 bpw，Q4_K_M-M64；Q8_0 K/V；每槽 160K 上下文。
- 配置：自动激进；temperature 0；Medium reasoning；对照普通 Decode 与 MTP，并包含视觉请求。
- 请求矩阵：20K、100K、150K。普通多轮首轮上限 768 token，后续最多 5 轮、每轮 192 token。双槽矩阵始终只有一个活跃请求，不是双 Decode 并发压力测试。
- 汇总：134 个有效请求，生成 39,416 token，实际 Prefill 3,294,951 token，复用 KV 8,608,767 token。
- SSD session cache 被禁用；结果不覆盖 SSD spill/restore 与跨槽 seed。

## 视觉与资源观测

视觉请求矩阵的图片轮分布在第 1、3、5 轮。图片在第 3/5 轮插入时，该轮 `cached_n=0` 是当时视觉 MRoPE 切换策略下的预期重建；后续纯文本轮恢复完整 KV 命中。视觉 MTP 的 100K Prefill 约 552–559 tok/s，普通单槽视觉约 927 tok/s。测试报告将其主要关联到 MTP 固定资源使实际 Prefill lane 减少；这是该次资源规划的观测，不应外推为所有显卡/配置的必然结果。

| 配置 | Arena GiB | Expert blocks | 最终 ubatch | 实际 Prefill lanes | dynamic state GiB | readback OOM |
| --- | ---: | ---: | ---: | ---: | ---: | --- |
| 单槽普通 | 16.21 | 25,336 | 4096 | 3 | 2.70 | 否 |
| 双槽、单活跃、普通 | 15.88 | 24,821 | 4096 | 1 | 5.39 | 否 |
| 单槽 MTP | 14.28 | 22,321 | 4096 | 2 | 3.01 | 恢复后通过 |
| 双槽、单活跃、MTP | 13.29 | 20,773 | 2048 | 2 | 6.02 | 否 |

原报告记录单槽 MTP 启动时懒申请 160 MiB readback 曾出现物理 OOM，释放约 3.76 GiB 空闲 Host-DMA 映射后重试恢复。该结果属于告警恢复，不能记作无异常通过。

## 结论与范围限制

- 报告汇总的 134 个有效请求中，重复输出标记 0 次、非人为请求失败 0 次；没有观察到 device lost、panic 或 scheduler batch failure。
- 这不是两个槽同时 Decode 的并发测试，也不覆盖 SSD session cache 的 spill/restore。
- 双槽单活跃时 Prefill lane 从 3 降至 1，是观测到的约 39% Prefill 回退；不是双请求争抢 GPU。
- 单槽 MTP 多轮 KV 未命中、视觉插图轮 KV 重建及 readback OOM 恢复都必须与总体验收结论并列保留，不能只摘录速度提升。
- 报告记录的 MTP 收益存在深度与内容敏感性，尤其双槽 150K 后段为 33.48 tok/s；不应只引用平均值或最佳区段。
