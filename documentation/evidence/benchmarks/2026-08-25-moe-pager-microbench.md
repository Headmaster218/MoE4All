# MoE 计算、RAM/SSD 提升与调度微基准

这组 `infr-vulkan` 专项集成测试使用实际分页专家内核、`MoePagerSession`、完整/包容式 RAM 路径和 `FileBlockIo`，不包含 CLI、模型图、KV、Attention 或服务器。因而下面的微秒数不能直接折算成端到端 Decode tok/s。35B 的 Q5_K/Q6_K 块为 0.688/0.820 MiB；122B 的 IQ4_XS/Q5_K/Q6_K 块为 1.594/2.063/2.461 MiB。SSD 读使用不重叠的首次触碰 1 GiB 窗口，避免把 OS cache 命中计作磁盘性能。

阶段记录注明增量编译耗时 2.66 s，5 次筛选运行合计 14.1 s；原报告标识为 `moe-schedule-cost-final2-20260824-203548/report.md`。这两项是测试开销和产物溯源，不是模型推理耗时；原报告本身未随文档分支保存。

## 为何保留完整 UGD 批次

UG 后另发一次 D 需要首次提交 25-50 µs、记录/提交交接 20-50 µs；常驻 UGD 拆分后多出 54-118 µs。35B 的 UG 仅计算 9-22 µs、122B 为 14-70 µs；RAM 中 D 提升分别约 45-431/109-1348 µs，SSD 中 122B 为 0.94-4.92 ms。UG 计算窗口不足以掩盖提升与第二次提交。模拟中从 RAM 拆分 Down 通常慢 0.1-0.75 ms，从 SSD 拆分通常慢 0.6-3.1 ms；少数正端点小于 SSD 测量波动。

当时保留的调度策略是先计算共享与已常驻完整 UGD，同时批量提升全部 miss，再计算 miss UGD。常驻优先可在 122B 多 miss 情形掩盖数百 µs。独立 Vulkan Host DMA 的 20-40 MiB 大块复制可达 23-25 GiB/s，但不能据此宣称单专家提升已达到这个速率：提交固定成本、import 尾段和队列依赖仍存在。

此页保存当时否决 UG/D 按 tier 分支的依据；现行调度仍应以[0.9.0 并发调度](../../architecture/runtime/parallel-scheduler.md)及目标设备的重新测量为准。
