## Round 61：prefill 成果复测稳定；MTP 这条路不通

### prefill 复测（两次独立运行）

```
prefill 1431 tok @ 25 tok/s (57187 ms)
prefill 1431 tok @ 25 tok/s (56421 ms)
```

两次差 1.3%。**2.1 倍（12→25）的结论是可靠的，不是单次抖动。**

### MTP：这个模型没有 MTP 头

解析 GGUF 头，42 个张量里**没有任何 mtp / draft / nextn 张量**：

```
MTP 相关张量: 无
总张量: 42
```

本机也没有带 MTP 头的 V4.1 模型文件（`dsv41-iq2xxs-pack-mtp*` 目录里只有
`ds4.txt` 和 `engram.bin`，没有 gguf）。

**代码侧 MTP 支持是完整的**（`INFR_MTP=1` + 一批 `INFR_NO_MTP_*` 开关，
`crates/infr-llama/src/mtp/`），但要跑起来必须有带头的模型。

**所以 MTP 不是当前可用的手段。**

### 现状汇总

|---|---|---|
| **prefill** | **25 tok/s**（1431 tok / 57s） | ✅ 已从 12 提升 2.1 倍，两次复测稳定 |

### decode 到 27.7 还差什么

不是再找第 10 个瓶颈，而是需要**减半每 token 的 GPU 工作量**。

本模型的硬约束：
- 40 层 × top-6 = 每 token 240 个专家实例
- 专家缓存命中率 59.9%
- 权重总量 166 GiB，显存装不下

**poorseek 的 27.7 是在 RTX 4090 24GB + 90GB DDR4 + `--route-bias 1.0`（近似路由）下测的，
本就不是同口径。** 我们跑的是精确路由。

### 结论

**这一轮把可做的做了：prefill 提 2.1 倍并验证稳定。decode 停在 6.2，
且已证明不是"还有瓶颈没找到"，而是这套配置下的真实成本。**
