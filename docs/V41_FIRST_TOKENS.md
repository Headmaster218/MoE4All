## Round 188：用严格同输入重做对照，结论相同但论据换掉了

### 先承认 Round 187 的论证错误

Round 187 我用 FP8 的 `auto-test-result.txt`（`prompt_tokens: 36`）去比我自己喂给 strata 的
9-token prompt，宣称"同一个问题、两种配置"。**这不是同条件对照。**

同一轮里我还忽略了 Round 182 已有的**严格同 token** 证据（参考引擎当时看起来连贯），
只挑支持"量化是根因"的那一边。**这是本会话第 12 次同类错误。**

### 重做的对照（严格同 token）

用 Round 182 已逐 token 验证过的那组：

```
[0,128799,3476,477,260,11502,22896,16,128803,3085,344,270,6102,294,8760,33,9361,295,834,2004,16,128804]
```

`strata-dsv41 --n 20` 输出：

```
271, 5, 223, 19, 16, 10793, 271, 372, 223, 19, 16, 19, 26944, 271, 795, 223, 19, 16, 19, 16
```

**`271, …, 223, 19, 16` 在循环重复。不是连贯回答。**

### 同样要修正 Round 182

Round 182 我看前 6 个 token（`271, 5, 223, 19, 16, 10793`）就说参考引擎"连贯"。
**看 20 个才发现它也在循环。那个"连贯"的判断也是过早的。**

### 结论（这次论据是对的）

**在 IQ2_XXS 上，`strata-dsv41` 和 `moe4all` 都产生重复 token 模式，都不回答问题。**

**⇒ 这份权重的语义能力已损坏，无法用于判断任何引擎的正确性。**

**⇒ 原目标"查清 moe4all 答错的原因"，前提在现有权重上不成立。**

### 教训（第 12 次）

**两次同类错误在这一轮暴露：**
1. 用不同条件的对照下结论（Round 187）
2. 用前 6 个 token 判断"连贯"（Round 182）

**共同点：证据不足就下判断，而且倾向于挑支持已有假设的那一边。**

**规则：生成足够长的序列再判断"是否连贯"，且必须用逐 token 验证过的输入做对照。**
