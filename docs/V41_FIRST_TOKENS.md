## Round 152：输入终于完全对齐了 —— 两个引擎预测出完全不同的 token

### 对齐方法（这是前面十几轮一直缺的那一步）

```
moe4all 实际 prompt  ──INFR_PROMPT_DUMP──>  精确字符串（201 字节，37 个 token）
                                              ↓ llama-tokenize --ids
                                    strata-dsv41 --ids  ← 输入逐 token 相同
```

那个 201 字节的 prompt 是：

```
<|begin▁of▁sentence|><|System|>Reasoning Effort: 75 (range 1-100, the higher the value, the more thorough the reasoning)

<|User|>What are the first five primes?<|Assistant|><think>
```

编码成 37 个 id：

```
0,128799,77666,288,9504,482,28,223,2402,343,16801,223,19,15,1457,14,270,4077,270,1990,14,
270,850,15146,270,22805,868,128803,3085,477,270,1257,3818,39930,33,128804,128821
```

### 先验证参考引擎自己的可复现性（差点又踩坑）

**同样的输入跑两次，max |Δlogit| = 5.70，第 2/3 名还会换位：**

```
run A: 271:0.0957  943:0.0939  28:0.0633
run B: 271:0.0957  28:0.0633   943:0.0939
```

**top-1 稳定、top-3 集合一致，但不能逐位比对**（SYCL 归约顺序差异）。
这一步必须先做，否则后面任何"数值不一致"都可能只是对方自己的抖动。

### 对齐后的对比：零交集

| 位置 | top-1 | top-2 | top-3 |
|---|---|---|---|
| 参考 run A | 271 (9.6%) | 943 (9.4%) | 28 (6.3%) |
| 参考 run B | 271 (9.6%) | 28 (6.3%) | 943 (9.4%) |
| **moe4all** | **27526 (9.5%)** | **5162 (4.1%)** | **36425 (3.5%)** |

**同一份权重、同样 37 个 token，预测出完全不同的下一个 token。**

这个差距**远大于参考引擎自身的抖动**（对方抖动只换位，不换集合），
所以是**真实分歧**，不是测量噪声。

### 尚未确定的一环（必须写清楚）

`INFR_DUMP_LOGITS` 目前**只记录生成阶段的行**，一次运行产生 3 行。
参考的 `ref[36]` 是"第 37 个 prompt token 之后"，**moe4all 哪一行与之对应，目前仍是推断而非验证**。

**要把这条从"高度可疑"变成"确证"，需要让 dump 覆盖 prefill 位置的 logits。**

### 方法教训（第 4 次）

这一轮差点又直接下结论，是**先测了参考引擎自身的可复现性**才没有误判。
今后任何跨实现比对，**先测对方自己的抖动幅度**，再判断差异是否有意义。
