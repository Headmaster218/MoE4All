## Round 191：两个实验共同推翻了我自己的诊断方向

### 实验一：提高专家精度，输出逐位不变

```
pack-q2k-all (全 IQ2_XXS):        11111, 16, 455, 6102, 294, 8760, 344, 11111
mixed-mxfp4-l0-19 (前20层 MXFP4): 11111, 16, 455, 6102, 294, 8760, 344, 11111
```

**前 20 层专家精度提高约 2 倍（18.8 MB vs 9.1 MB/expert），输出**一位都不变**。**
**⇒ 专家量化不是根因。**

### 实验二：换完全不同的句式，仍然复读

```
输入: One plus one equals two. Two plus two equals
输出: 1234, 16, 8819, 9615, 1234, 16
解码: four and two plus two equals four and
```

**把 `two plus two equals` 原样复制，再插入 `four and`。**
**⇒ 复读行为与句式无关。**

### 结论：这是模型的**续写行为**，不是任何引擎的 bug

**三条证据：**
1. `strata-dsv41` 是独立参考实现，同样复读
2. 提高权重精度不改变行为
3. 换句式也复读

**⇒ 模型在没有 chat template 的**裸文本**上，做的是"接话"而不是"回答问题"。**

### 这解释了什么

| 现象 | 真实解释 |
|---|---|
| `Germany is` → `Paris` | 接续文本时复制了前文的答案 |
| `Two plus two equals` → 复制 `two plus two equals` | 接续模式，不是算术 |
| `2+2=` → 重复 token | 同上 |
| 提高精度无变化 | 行为来自结构，不来自精度 |

### 我此前的诊断方向是错的

**我一直假设"引擎实现有 bug 导致答错"，用了：
- 裸文本 prompt（绕过 chat template）
- `--ids` 直接喂 token（同样绕过）

**⇒ 这些都是"让模型续写文本"，而模型**本来就会续写文本**。用它判断"引擎对错"无效。**

**⇒ 本会话从 Round 130 起的大部分"答错"观察，都是这个方法论错误的产物。**

### 正确做法（下一轮）

**必须用**完整的 chat template** 测试：

```
<|begin_of_sentence|><|System|>...<|User|>问题<|Assistant|><|think|>
```

**而 `infr` 的默认模板已经生成这个格式（见 `INFR_PROMPT_DUMP`）。**
**所以应该直接跑 `infr run "问题"` 看它是否答对，用**模型原生格式**判断。**

**这条从未被真正测试过——我一直在用覆盖或简化格式。**
