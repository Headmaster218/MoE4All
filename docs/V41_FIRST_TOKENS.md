## Round 153：对齐后的实际生成对比

### 参考引擎 vs moe4all，同一 37 token 输入

| | 生成的 token |
|---|---|
| 参考 `strata-dsv41` | `271, 671, 1257, 3818, 39930, 477, 223, 20` |
| **moe4all** | 解码成文本 = `**  **`（星号与空格） |

注意参考生成的第 3–5 个 token（`1257, 3818, 39930`）**正是 prompt 中间那段**，
即参考引擎在**重复输入模式**。

### 这个结果要小心解读

**参考引擎自己也没有在回答问题** —— `<think>` 之后复制输入模式不是推理。
所以这个 benchmark 输入（`1k.ids` 那种重复串）对两个引擎都不是有意义的问答。

**但它仍然说明一件事**：同样面对这个输入，
- 参考引擎的反应是**自洽的复制**
- moe4all 的反应是 `**  **`（语法上就是碎片）

**⇒ 分歧真实存在，但用这个输入定位"答错原因"价值有限。**

### 下一轮改用真实问答输入

`What are the first five primes?` 本身就是合格的问答 prompt，
只是参考引擎在裸 ids 模式下没进入回答状态。需要确认：
- 是裸 ids 缺少对话格式导致的（那就补 system/user 标记）
- 还是这个模型在短 prompt 上本来就这样

`INFR_DUMP_LOGITS` 只覆盖 `is_decode` 分支，prefill 不产生 logits，
所以逐位置对齐 prefill 需要动计算图；先用真实问答输入把方向确认下来。
