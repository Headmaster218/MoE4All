## Round 30：IQ1_M 的成本结构 —— 34.8 ms 固定 + 58.9 μs/槽

### 实验：改变 chunk 大小

```
ub=128:  38.9s  63.90%  444 次   87.6 ms/次   (896 槽/次)
ub=256:  38.8s  63.97%  276 次  140.4 ms/次   (1792 槽/次)
```

### 两条结论

**1. 总时间与 chunk 大小几乎无关**（38.9 vs 38.8 秒）。

调用少了 61%（444→276），但总时间不变——**总工作量由总槽数决定，切多大都一样。**
这正是 Round 10 就观察到的「与 ubatch 无关」，但当时没有正确的归因；现在有了。

**2. 单次耗时不为纯线性**

```
896 槽  →  87.6 ms   (97.8 μs/槽)
1792 槽 → 140.4 ms   (78.3 μs/槽)
```

槽数翻倍，时间只涨 1.6 倍。线性拟合 `t = a + b·slots`：

```
a = 34.8 ms        （每次调用的固定开销）
b = 58.9 μs/槽     （按槽计的变长部分）
```

**固定开销占 34.8/87.6 ≈ 40%（小 chunk 时）、34.8/140.4 ≈ 25%（大 chunk 时）。**

### 为什么这条对优化有用

- 想省那 40% 的固定开销 → **增大 chunk**。但 Round 10 已证明总时间不随 chunk 变，
  所以固定开销虽然存在，**不是**可省掉的那部分（增大 chunk 会把变长部分也拉长）。
- 真正要做的是**降低每槽的 58.9 μs**。那个数是 Round 29 说的「1 行 × 5120 × 2304 的乘加效率低」。

### 与 Round 29 的算术交叉验证

Round 29 算过：一次 1792 槽的调用理论只要 1.4–4.2 ms（按 10–30 TOPS），实测 140.4 ms。
现在拆开看：**34.8 ms 固定 + 1792×58.9μs = 105.6 ms**。

**即使扣掉固定开销，每槽 58.9 μs 仍然对应极低的有效算力**——
单槽是 `1×5120×2304 = 11.8 M MACs`，58.9 μs ⇒ **0.4 TFLOPS**。与 Round 29 的 0.30 TFLOPS 一致。
