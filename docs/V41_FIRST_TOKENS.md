## Round 46：k=5120 的对照实验 —— 精度偏差 ≠ 返回 0

### 想法

IQ1_M 的真实形状是 `k=5120`（每行 20 个 256-block），而测试用 `k=256`（每行 1 个 block）。
**形状差 20 倍可能掩盖问题**，所以把测试改成真实形状。

### 结果：对照组先倒了

```
Iq2S xp mismatch at 0: got -1.6820084 want -1.6232196
```

**IQ2_S 不通过——但不是返回 0，而是偏差约 3.6%。**

这是**数值精度**问题（int8 量化 + 长累加的舍入），不是结构错误。

### 这个对照很有价值

| 情形 | 表现 | 性质 |
|---|---|---|
| IQ2_S @ k=5120 | 偏差 3.6% | 精度 |
| IQ1_M @ k=256 | **精确的 0** | **结构** |

**「精确的 0」和「偏差 3.6%」是两类完全不同的失败。**
前者意味着什么都没算出来，后者意味着算出来了但有误差。

### 已改回 k=256

因为 k=5120 让对照组也失去通过基线，无法继续用作对照。

### 状态

无代码改动，工作树干净。PR #183：78 commits。

### 下一步

「精确的 0」意味着 IQ1_M 的 MMQ 路径**根本没有产生任何贡献**。
在 k=256 下（每行 1 块，`ib == sub`，地址最小化）仍然全 0，
说明问题不在 k 相关的地址算术上——**更可能是 `q_lo`/`q_hi` 的积本身就为 0**，
例如 grid 表 `G_IQ1S` 没被正确加载（`grid_init()` 依赖 `native_grids.glsl`）。

**下一轮该验证 `grid_init()`**：如果 `IQ1S_GRID` 全是 0，那么所有 `y_j` 都是 0，
`q_lo`/`q_hi`/`acc` 自然全 0——这能完美解释「精确的 0」。
