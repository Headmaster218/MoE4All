## Round 59：对账 —— 空档里有 68% 完全没有解释

### 为什么不猜了，改成对账

前面 7 个假设全部死在 A/B 上。共同点是：**每个都是"看起来很合理"的推理**。
这次不再推理，只做**加减法**：把已知的 host 开销全部加起来，看能不能填满 1.55s 的空档。

### 账

```
span                = 4410 ms
main_busy (GPU 忙)   = 2860 ms
outside (空档)       = 1550 ms
```

已知 host 侧开销（全部来自实测）：

| 项 | 实测值 |
|---|---|
| `record_lifetime` | 400.6 ms |
| `recorder_acquires.acquire_time` | 33.2 ms |
| `vulkan submit.cpu_submit_time` | 35.7 ms |
| `backend setup_time` | 25.7 ms |
| `dedicated DMA.cpu_submit_time` | 7.8 ms |
| **合计** | **503.0 ms** |

### 结果

**1550 − 503 = 1047 ms 无解释。**

已知 host 开销只占空档的 **32%**，**剩下 68% 不知道花在哪。**

### 这条为什么比前 7 个假设可靠

它不是"我觉得 X 是瓶颈"，而是**"已知项加起来填不满，所以还有 1047ms 的未知项"**。
这是一个**存在性结论**，不依赖对未知项性质的猜测——无论它是什么，它必须存在。
