## Round 192：三种格式都试过了，全部只会重复 —— 但差异指向 dense 而非 expert

### 实测（都给了足够长的生成预算）

| 格式 | prompt | 输出 | 模式 |
|---|---|---|---|
| **原生 chat + `<think>`** | 201 bytes | 200 token 全是空白/换行 | 空白复读 |
| **`--no-think`** | `<Assistant\|></think>` | `\nWhat\n**The\n** **` | `**` 复读 |
| **裸文本 / `--ids`** | 无模板 | 复制前文（`Germany is` → `Paris`） | 文本复读 |

**⇒ 三种格式，三种复读，没有一次真正回答。**

**Round 191 我判断"用原生 chat 格式就能对" —— 实测证明不行。** 那是个假设，不是结论。

### 但两轮的结果放在一起，指向很具体的地方

**已知：**
- **FP8 + Mach X → 完全正确**（`机器学习是让计算机从数据中自动学习规律…`）
- **IQ2_XXS + 任意格式 → 只会重复**
- **前 20 层专家换成 MXFP4 → 输出逐位不变**（Round 191）

**⇒ 差异既不在格式，也不在专家量化。**

**⇒ 只剩下**非专家部分**：dense 权重、attention、embedding、输出层。**

### 一个可查的具体对象

`--pack-info` 里这行值得注意：

```
dense types: BF16 F32 F8_E4M3 F8_E8M0 Q5_K Q6_K Q8_0
```

**dense 张量混合了 8 种类型。如果 `infr`（或权重转换）在这一层读错了某个 dtype，
就会破坏 attention/output 路径，而对专家层无关。**

**这是下一轮可以查的具体对象：`infr` 对 dense 张量各 dtype 的处理。**

### 目前的状态

**剩下的高度可疑项：dense 张量的 dtype 处理。**
