优化路径的观测限制：CPU 轨只记录主控制线程；notice producer 的缓存管理、专家准备和上传没有继承 trace context，DMA 轨因此可能缺失，空轨不表示没有搬运。CPU wait 包含等待 producer，不能算作纯 CPU 忙碌。GPU 主队列有真实时间戳，但条件跳过仍会执行 query marker；不对优化路径强行推导整层边界。普通路径保留旧图的 CPU 层与 GPU 层估算。

分类含义与测量口径
分类含义

一个普通 Decode step 推进所有活跃路各一个 token，包含输入准备、模型执行、采样和 token 回调；不含前面的请求排队和大段 Prefill。主队列区间包含依赖、复制、屏障和停顿，不是 ALU 利用率。CPU wait 常与 GPU 工作重叠，不能直接当作可删除开销。P50/P90 标记选择最接近该分位数的真实样本，不拼接各阶段中位数。

层轨使用 L0 起的编号。每层开始/结束由 CPU 算子顺序推导，包含该层 PLE（若有）、GDN/QSA、MoE 和末尾 HC injection 的 CPU 执行区间；不代表 GPU 的整层执行时间。条内深线是原始 expert_layer span，表示 CPU 专家处理阶段。绿色起点、红色终点延伸到 CPU 轨，不延伸到 GPU 轨。旧 trace 未记录整层 GPU 起止，不据此估算 GPU 层耗时。

GPU 估算轨以末尾 HC injection 所在 recorder 的提交内第一个 HC completion interval 为边界锚点；每层必须对应独立提交。该版本 early submit 会将 MoE 和末尾 HC 分开，不能沿用旧图的同提交 MoE→HC 匹配规则。单独 HC 使用区间终点；HC injection 与下一层 norm 合并时，按该步单独 HC 区间的中位耗时估算切点，无参考则取中点。同类算子耗时只是近似稳定，会受设备、路数、融合、缓存和调度影响。边界定位范围是整个对应 HC 区间，不是严格误差界或统计置信区间；层区间包含队列停顿、等待与提交空隙，不是纯计算。缺少或歧义锚点的样本不强行插值。原 CPU 和提交统计不变。
